# Ubuntu 24.04: установка форка с профилями и прокси

Один процесс Dario обслуживает все аккаунты. Для входа каждого профиля запускается отдельный Chromium с собственными cookies и каталогом данных. Полноценная Ubuntu Desktop не нужна: Xvfb создаёт виртуальный экран, Openbox показывает окна, noVNC даёт доступ из браузера на вашем компьютере.

## Установка на чистом сервере

Подключитесь по SSH и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/DarkTwistter/dario/feat/account-proxy-profiles/deploy/ubuntu/setup.sh -o dario-setup.sh
sudo bash dario-setup.sh
```

Скрипт сам определяет x86_64/arm64, ставит зависимости, Node 22 с проверкой SHA256, Bun 1.4.4 и подходящий Chromium, собирает форк и создаёт пользователя `dario`. Устанавливает две systemd-службы и команду `sudo darioctl`. Playwright используется для загрузки браузера, Dario не получает новых npm-зависимостей времени выполнения.

Секреты генерируются при первой установке и при повторном запуске сохраняются. Существующий `/opt/dario` не сбрасывается и не обновляется автоматически. Скрипт не меняет SSH, UFW, системную связку ключей или глобальные ограничения user namespaces.

Перед запуском служб выполняются тесты браузера и двух независимых прокси. Если VPS запрещает namespaces или браузер не запускается со своей штатной песочницей, установка останавливается с ошибкой. Автоматического запуска без изоляции и флага `--no-sandbox` нет.

На некоторых VPS, в LXC/OpenVZ и на ограниченных ядрах user/network namespaces недоступны. В этом случае нужны разрешённые namespaces у хостера или обычная VM; повторный запуск после устранения причины сохраняет профили.

## Подключение к окнам входа

На своём компьютере выполните, заменив `USER@SERVER`:

```bash
ssh -N -L 3456:127.0.0.1:3456 -L 6080:127.0.0.1:6080 USER@SERVER
```

Откройте **http://127.0.0.1:6080/vnc.html**, нажмите Connect. Пароль на сервере:

```bash
sudo cat /etc/dario/vnc-password
```

Dario, VNC и noVNC слушают только loopback. Открывать порты 3456, 5900 или 6080 в интернет не требуется. noVNC показывает общий рабочий стол администратора: браузеры профилей имеют разные хранилища, но это не изоляция рабочего стола для разных людей.

## Первый аккаунт

Через веб-интерфейс: откройте **http://127.0.0.1:3456/analytics/ui** и нажмите **«Аккаунты»**. Прямая ссылка: **http://127.0.0.1:3456/profiles/ui**.

Скопируйте admin-токен на сервере:

```bash
sudo sed -n 's/^DARIO_ADMIN_TOKEN=//p' /etc/dario/dario.env
```

Введите его на странице управления. Форма позволяет создать профиль с адресом, логином и паролем прокси, email, часовым поясом и языком. Нажмите **«Создать профиль»**, затем **«Войти»** у нового аккаунта. Кнопка **«Открыть браузер сервера»** переводит в noVNC, где вы завершаете вход. После подтверждения аккаунт автоматически появляется в пуле. Admin-токен остаётся только в памяти страницы; пароль прокси сервер обратно не возвращает.

Кнопки **«Настройки»**, **«Включить/Отключить»** и **«Проверить IP»** позволяют управлять профилем без CLI. Проверка открывает CleanIP в браузере сервера на 30 минут по умолчанию. Если установка уже была выполнена до появления веб-управления, обновите код и сборку:

```bash
sudo git -C /opt/dario pull --ff-only
sudo env PATH=/opt/dario-node/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin npm --prefix /opt/dario run build
sudo systemctl restart dario
```

Вариант через CLI:

На сервере:

```bash
sudo darioctl profiles create work
```

Введите URL HTTP/HTTPS-прокси с авторизацией, например `http://user:password@proxy.example:8080`, затем email Claude, часовой пояс выхода и язык браузера (последние поля можно пропустить). Ввод скрыт, пароль прокси не попадает в историю shell. Специальные символы логина/пароля должны быть URL-encoded (`@` → `%40`, `#` → `%23`). SOCKS напрямую не поддерживается.

```bash
sudo darioctl profiles login work
```

На странице noVNC появится отдельное окно Chromium. Завершите вход через email-код/ссылку или Google и подтвердите доступ. Почтовую ссылку открывайте в этом же окне, либо используйте код из письма. Собственного пароля Claude нет. Пароли Google/почты Dario не сохраняет.

Обычные окна входа и CleanIP запускаются **без WebDriver, DevTools/CDP и headless**. Email вводится вручную, автоматического заполнения полей нет. Для прокси используются параметры запуска Chromium и локальный шлюз; код OAuth возвращается обычным HTTP callback. Язык применяется через настройки Chromium, часовой пояс на Ubuntu — через `TZ` отдельного процесса (включая всплывающие окна). Например, для выхода в Нидерландах укажите `Europe/Amsterdam`, затем полностью закройте старое окно и откройте профиль заново. Менять системный часовой пояс всего сервера не нужно.

Автоматизированный DevTools-контроль включается только отдельной опцией в headless self-tests установщика и не используется пользовательскими кнопками «Войти»/«Проверить IP». Такие тесты проверяют сеть и UI, а не доказывают отсутствие признаков автоматизации у собственных тестовых окон.

Код вернётся в локальный callback Dario через разрешённый маршрут шлюза. Обмен кода и получение профиля выполняются через прокси аккаунта. После сохранения токенов Chromium закрывается; аккаунт сразу добавляется в работающий пул, перезапуск Dario не нужен.

Для других аккаунтов повторите команды с другим именем и другой прокси.

```bash
sudo darioctl profiles list
sudo darioctl profiles disable work
sudo darioctl profiles enable work
sudo darioctl profiles check work
```

Время жизни окна **«Проверить IP»** задаётся в `/etc/dario/dario.env`: `DARIO_BROWSER_CHECK_TIMEOUT_MINUTES=60` — один час, `DARIO_BROWSER_CHECK_TIMEOUT_MINUTES=0` — без автоматического закрытия. Допустимы целые значения 0–1440; по умолчанию 30 минут. После изменения выполните `sudo systemctl restart dario` и откройте окно заново. Перезапуск службы закрывает уже открытые окна. CLI-команда `profiles check` по-прежнему ждёт Enter, а окно авторизации закрывается после получения токенов или при истечении пятиминутного срока входа; этот параметр относится к проверке IP.

`check` открывает CleanIP в **том же** браузерном профиле через **ту же** прокси. Запустите проверку на сайте; после просмотра нажмите Enter в SSH, чтобы закрыть окно. Балл зависит в том числе от репутации и поведения прокси; он не является официальным рейтингом Anthropic. Максимальный балл без проверки конкретного выхода не обещается.

## Язык и часовой пояс

Перед входом можно создать профиль из файла. Сохраните `/root/work-profile.json` с правами `0600`:

```json
{
  "proxyUrl": "http://user:password@proxy.example:8080",
  "email": "account@example.com",
  "timeZone": "Europe/Berlin",
  "locale": "en-US",
  "browserIsolation": "external"
}
```

`darioctl` читает файл уже от пользователя `dario`, поэтому для файла под `/root` сначала передайте его через защищённый каталог, доступный этому пользователю:

```bash
sudo install -o dario -g dario -m 0600 /root/work-profile.json /var/lib/dario/work-profile.json
sudo darioctl profiles create work --file=/var/lib/dario/work-profile.json
```

Выбирайте реальный часовой пояс выхода и подходящие языковые настройки. User-Agent, Canvas и WebGL не подменяются. Для существующего профиля настройки находятся в `/var/lib/dario/.dario/profiles/work/profile.json`; изменение прокси прерывает соединения, новые настройки используются при следующем запуске браузера.

## Подключение клиентов

Посмотреть сгенерированные ключи на сервере:

```bash
sudo cat /etc/dario/dario.env
```

Для клиента на вашем компьютере оставьте SSH-туннель работающим и задайте:

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:3456
export ANTHROPIC_API_KEY='<значение DARIO_API_KEY>'
```

Для OpenAI-совместимого клиента используйте `http://127.0.0.1:3456/v1` и тот же ключ. Персональные Claude-аккаунты при этом остаются в одном пуле Dario.

## Сетевая изоляция

На Ubuntu launcher создаёт **новое user/network namespace для каждого браузера**, поднимает только loopback и проверяет отсутствие внешних интерфейсов и default route для IPv4/IPv6. Локальный relay соединяет браузер с Unix-сокетом Dario. Только шлюз Dario знает адрес и пароль внешней прокси.

```text
Chromium в сети без интернета
  → loopback relay → Unix-сокет Dario → прокси профиля → сайт
```

DNS целевых сайтов выполняется на стороне прокси. Chromium дополнительно блокирует локальный DNS resolver, DNS prefetch, прямой WebRTC UDP и QUIC. Прокси-шлюз не имеет прямого внешнего fallback; единственное прямое исключение — точный локальный OAuth callback. AppArmor-разрешение namespaces добавляется только для выделенного launcher и установленного Chromium, не глобальным sysctl.

Запросы Dario также несут прокси выбранного аккаунта: inference, повторные запросы, OAuth, refresh, профиль, каталог моделей и presence. Отсутствующая/повреждённая/отключённая конфигурация блокирует аккаунт. Отключённые профили исключаются из выбора пула; активные запросы и браузерные туннели прерываются при обнаружении изменения, обычно за 250 мс. Уже отправленные байты отозвать нельзя.

Один адрес прокси не гарантирует один внешний IP: если провайдер ротирует выход на каждом соединении, браузер и Dario могут иметь разные выходы. Для постоянного IP нужна соответствующая настройка самого провайдера прокси.

Изоляция namespace относится к браузеру. Dario работает в сети сервера, его ограничения обеспечиваются транспортом аккаунтов. Для дополнительного запрета на уровне ядра можно ограничить egress systemd-службы списком IP всех разрешённых прокси (`IPAddressDeny=any`, `IPAddressAllow=localhost` и IP прокси); такой список нужно поддерживать при изменении прокси. Скрипт не устанавливает неподтверждённые IP-правила автоматически.

## Файлы и диагностика

| Путь | Содержимое |
|---|---|
| `/opt/dario` | Код форка |
| `/var/lib/dario/.dario/accounts` | OAuth-токены аккаунтов |
| `/var/lib/dario/.dario/profiles` | Прокси и браузерные каталоги |
| `/etc/dario/dario.env` | API/admin-ключи и окружение службы |
| `/etc/dario/vnc-password` | Пароль удалённого рабочего стола |
| `/etc/dario/install-manifest` | Установленные версии и Git-коммит |

```bash
sudo systemctl status dario dario-desktop
sudo journalctl -u dario -u dario-desktop -n 100 --no-pager
```

До первого входа `/health` возвращает **503**: пустой пул ещё не может обслуживать запросы. Это ожидаемо. Файлы токенов/прокси имеют права `0600`, каталоги профилей — `0700`; секреты хранятся на диске, а не в аппаратном хранилище.

На Ubuntu/macOS блокировка браузера теперь удерживается ядром через `flock` (небольшой процесс Python 3 держит её до закрытия окна). Само наличие `browser.lock` нормально и не блокирует запуск: после падения Dario блокировка освобождается автоматически. Дополнительно проверяется `SingletonLock` Chromium, чтобы не открыть профиль поверх оставшегося работающего браузера. Не удаляйте файл блокировки у активного окна. Для Windows сохраняется прежняя файловая блокировка.

Синтаксис установщика проверен локально; полный запуск служб и namespace-тесты установщик выполняет на целевом Ubuntu-сервере. Тесты не вызывают Anthropic и не расходуют подписку.
